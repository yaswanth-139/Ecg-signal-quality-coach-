ECG Signal Quality Coach
Find out which parts of an ECG recording are clean enough to analyze, and why the rest are not.
Live demo: <ADD YOUR .streamlit.app LINK HERE>
Disclaimer: This is an educational software prototype for ECG signal-quality assessment and preprocessing. It does not diagnose heart conditions, interpret cardiac abnormalities, replace a healthcare professional, or provide medical advice. Do not use its score or recommendations for clinical decisions.
The problem
ECG recordings pick up noise: baseline drift, power-line hum, muscle activity, motion, loose electrodes. Analysis run on noisy segments is unreliable, and it is hard to tell by eye which segments to trust.
What it does
Upload an ECG CSV (or pick a demo file). The app:
Filters the signal with a 0.5-40 Hz zero-phase Butterworth band-pass (optional 50/60 Hz notch filter).
Splits it into windows (4-10 s, default 5 s) and scores each window 0-100.
Labels each window good (green, score >= 70), caution (yellow, 40-69) or poor (red, < 40).
Names the problems found in each window and lists the segments that are safe to analyze.
Gives practical tips for getting a better recording.
Other outputs: raw vs filtered plot with detected R-peaks colored by window quality, a window-by-window report, raw metric values, and a CSV report download. A "Why quality matters" table compares heart rate and beat-to-beat variability (RMSSD) from the whole recording against clean windows only, to show how noise distorts them. It is there for that illustration only.
Problems it detects
Baseline drift / motion, high-frequency (muscle) noise, power-line interference, abnormal amplitude (spikes, loose electrode), inconsistent beat shape, too few detectable beats, flatline (electrode off) and clipping (amplifier saturation).

Score = 100 x weighted sum of sub-scores, then:
A severe problem in any metric (sub-score < 0.2) caps the window at 39 (poor).
Severe hum alone caps it at 55 (caution), because a notch filter fixes it.
Flatline (signal constant for 1 s or more) sets the score to 0.
Clipping (more than 5% of samples stuck at the min/max) caps it at 20.
AI engine
generate_ecg_data.py builds 6,000 synthetic 4-10 s ECG windows with random heart rate and waveform shape, plus randomly injected artifacts. Each window is labeled with the artifacts that were added (drift, hum, muscle noise, motion, pops, flatline, clipping). Occasional premature-looking beats and inverted leads are included and not labeled as noise.
ecg_features.py turns each window into 21 numbers: frequency-band power, waveform shape statistics, beat regularity.
train_ecg_model.py trains a Random Forest (300 trees, 80/20 train/test split) and saves ecg_quality_model.joblib.
Window score = 100 x (1 - highest weighted problem probability). Hum counts half. A problem is flagged at 50% probability or more.
Example run on 1,200 unseen synthetic windows: 97.9% agreement on usable vs not usable, 94.9% exact match on good/caution/poor. F1 per problem: baseline 0.95, hum 0.95, muscle 0.96, motion 0.87, pops 0.78, flatline 0.96, clipping 0.90. The app shows the exact numbers for the model it loads.

Input format
CSV with time and ecg columns (time in seconds or milliseconds), or a single column of samples. A header row is optional.
The sampling rate is detected from the time column. Without one, set it manually (50-5000 Hz).
The recording must be at least 5 s long and contain at least one full window. Missing values are interpolated.

Limitations
The AI engine is trained and tested only on synthetic ECG. The accuracy figures above are for synthetic windows, not real recordings. Validation on real data (for example PhysioNet recordings) is future work.
Thresholds and weights are heuristic prototype values, not clinical thresholds.
Single-lead signals only. The beat-shape check cannot tell noise from genuine changes in beat shape, so inspect flagged windows manually.
Windows do not overlap, and a final partial window is not scored.
The model is trained at 250 Hz. Other sampling rates are resampled.
